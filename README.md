# 🔍 How My Labs Are Documented

Each major project is designed as a small technical case study rather than only a configuration file.

A documented lab normally includes:

**1. Objective**
What the network is designed to accomplish.

**2. Topology**
A visual network diagram showing devices, interfaces, networks, VLANs, and routing relationships.

**3. Addressing Plan**
IP addressing, subnet information, VLAN IDs, and interface assignments.

**4. Configuration**
Relevant Cisco IOS configuration with explanations.

**5. Verification**
Commands such as:

`show ip route`
`show ip ospf neighbor`
`show interfaces trunk`
`show spanning-tree`
`show etherchannel summary`
`show access-lists`

**6. Troubleshooting**
Problems introduced or discovered during the lab and the process used to identify the root cause.

**7. Result**
Final connectivity and protocol verification.

# 🛠 Troubleshooting Approach

My labs emphasize troubleshooting in addition to configuration.

Typical workflow:

**Physical → Data Link → Network → Transport → Application**

I verify:

Interface status → VLAN/trunk state → Layer 2 topology → IP addressing → routing table → protocol neighbors → ACL/NAT policies → end-to-end connectivity.

The objective is not only to make a network work, but to understand **why it works and how to diagnose it when it fails**.
